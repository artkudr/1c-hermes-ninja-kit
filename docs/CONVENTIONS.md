# Конвенции (CONVENTIONS.md)

## Структура репозитория

```
1c-hermes-ninja-kit/
  install/install.sh        # идемпотентная установка окружения
  scripts/ninja.sh          # создание/список/обзор баз
  scripts/ninja_json.py     # работа с tools/projects.json (python на Windows)
  templates/                # шаблоны для новых баз (см. ниже)
  docs/INSTALL.md           # проверенные шаги установки и эксплуатации
  docs/DECISIONS.md         # обоснованные решения
  .env.example              # шаблон секретов (токен Напарника)
```

## Живой мост в 1С (1c-mcp-toolkit :6003)

- Прокси — один Docker-контейнер на машину (`1c-mcp-toolkit-proxy`, порт 6003,
  `--restart unless-stopped`), идемпотентный `docker run` (см. README).
- Обработка `MCP_Toolkit.epf` (на x86-платформе — `MCP_Toolkit_x86.epf`)
  живёт в сессии 1С; команды прокси передаёт long-polling-ом по каналу.
- MCP-сервер в Hermes: `hermes mcp add 1c-toolkit --url http://127.0.0.1:6003/mcp`.
- Пароли 1С — только вручную в диалоге входа; в конфиги/скрипты/.env не пишем.
- Разные dev-базы — разные каналы: `/C "startup;mode=proxy;url=...;channel=<имя>"`.

## Корни

- `PROJECTS_ROOT` (по умолчанию `C:/hermes`) — корень всех 1С-проектов.
- `PROJECTS_ROOT/tools/` — инфраструктура (НЕ база): `cfg/ context/ repos/
  scripts/ reports/ downloads/ engine/`, `.env`, `projects.json`.
- Движки/бинари живут в `tools/engine/…` (ничего в Program Files).
- Репозиторий ninja-kit сам лежит рядом с `tools/` в корне проектов.

## Структура 1С-базы (создаёт `ninja new`)

```
<имя>/
  src/cf/            # выгрузка типовой — read-only, НЕ в git (версия — notes/registry.md)
  src/cfe/<Расширение>/  # расширения — единственное, что линтуем/редактируем
  notes/registry.md  # реестр: версия типовой (одна строка), состав расширений
  notes/state.md     # КООРДИНАТОР: сводный стейт проекта (таблица задач, журнал)
  tasks/task_N/      # одна папка на задачу: README.md (карточка), request.md,
                     #   solution.md, assets/ (скрины), materials/ (файлы заказчика), _archive/
  docs/              # общая документация (не по задачам)
  reports/           # отчёты анализа (json/sarif), НЕ в git
  AGENTS.md          # правила работы (из templates/AGENTS.md.tpl)
  .gitignore         # src/cf, reports/ вне git
```

Эталон со всеми шаблонами — `templates/project/` (включая пример задачи task_1).

## Hermes-проект (обязательная привязка)

1 база = 2 сущности: каталог на диске (создаёт `ninja new`) + desktop-проект
Hermes с якорем на этот каталог (`project_create {name, path}`). Оба шага
обязательны при развёртывании базы. Переключение между базами — только
`project_switch <slug>`, не `cd`. Признак готовности: рабочий каталог сессии
= корень базы (проверять `pwd`).

## Имена

Имена баз и служебные файлы — только латиница (`A-Za-z0-9-_`; `task_1`,
`request.md`, `materials/`); **русское название задачи — только строкой** в
карточке (`task_N/README.md`, поле «Название») и в координаторе (колонка
«Название (рус.)»).

Имена РАСШИРЕНИЙ — как в 1С: кириллица допустима («Компас_Кьюбик»), папка
`src/cfe/<Расширение>` носит реальное имя расширения. Запрещены только `/` и `\`.

## Принцип

**Диск — единственный источник истины; сессия (Hermes) — интерфейс к документации.**
Всё ценное (запросы, решения, планы, скрины, файлы заказчика) живёт в файлах
проекта, не в истории чата. Использовать сессии короткими заходами, всегда
оставляя результат на диске.

## Git

- 1 база = 1 git-репозиторий (`git init -b main`; коммитов при создании нет).
- Ветки — на расширения.
- Conventional Commits: `feat(cfe/perprices): …`, `fix(…): …`, `docs: …`.
- Коммиты — только по явной команде владельца.
- `src/cf` и `reports/` игнорируются.

## Анализ

- Анализ кода — статический контур mcp-1c-autumn (порт lekot/mcp-1c на autumn-mcp):
  `bsl_search`, `xml_search`, `config_list`, `read_module`, `syntax_help_search`.
- Источник — `src/cfe/<Расширение>`; контекст типовой — `src/cf` (если непуст).

## Публикация

- Никаких секретов и личных путей; токены — в `.env` (вне git), `.env.example`.
- Идемпотентность скриптов: повторный запуск ничего не меняет.
- Публикация репозитория — только по отдельному «го», private по умолчанию.
