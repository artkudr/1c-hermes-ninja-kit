# Портирование MCP-серверов на autumn-mcp (OneScript)

## Что такое autumn-mcp

Библиотека для создания MCP-серверов на фреймворке ОСень (autumn) — пишется на BSL, выполняется через `oscript`.
- Транспорт: **только stdio** (на момент проверки; prompts/resources не поддерживаются, только tools).
- Установка пакетов: `opm install autumn`, `opm install autumn-mcp` (автор: autumn-library; версия для продвинутых аннотаций — autumn-mcp ≥ 1.1.0).
- Подключение к клиенту: в `mcp.json` / `~/.cursor/mcp.json` — `{ "mcpServers": { "<имя>": { "command": "oscript", "args": ["main.os"] } } }`.

## Аннотации (пример из README autumn-mcp)

```bsl
&ПараметрИнструмента(Имя = "number_1", Описание = "Число 1", Тип = "integer", Обязательный = Истина)
Перем Число1;

&Инструмент(Имя = "plus", Описание = "Складывает два числа")
Процедура ПриСозданииОбъекта()
КонецПроцедуры

&ВыполнениеИнструмента
Функция ВывестиРезультатСложения() Экспорт
    Возврат Число1 + Число2;
КонецФункции
```

- `&Инструмент(Имя=, Описание=)` — объявление tool'а (Имя — идентификатор для клиента).
- `&ПараметрИнструмента(Имя=, Описание=, Тип=, Формат=, ЭтоМассив=, Обязательный=)` — параметр inputSchema; `Имя` можно не задавать — будет транслит; `Тип` — json-schema тип (string/integer/boolean/number); `Формат` — например `date`.
- `&ВыполнениеИнструмента` — функция, вызываемая при вызове tool'а (должна быть `Экспорт`).
- Опционально `Функция АннотацииИнструмента() Экспорт` возвращает `Соответствие` с хинтами: `title`, `readOnlyHint`, `destructiveHint`, `idempotentHint`, `openWorldHint` → уходят в `tools/list` как `annotations` (клиент по ним спрашивает подтверждения и т.п.).

## autumn-mcpify — CLI → MCP

Превращает CLI-приложение на autumn-cli в MCP-сервер (stdio):
- Пометить подкоманду `&ДоступноВMCP` — она появляется как tool `путь_подкоманды_через_подчёркивание` (например `cf_compile`).
- Схема параметров генерируется рефлексией из `&Опция`/`&Аргумент`/`&НаборОпций`/`&Перечисление` — дублировать не нужно.
- Точка входа: `Запуск = Новый MCP_Запуск(); Запуск.Старт();` в mcp-скрипте; в обычный CLI-вход mcpify подключать не нужно (аннотации игнорируются без загрузки библиотеки).
- Сессионный кэш опций: значения `&Опция` запоминаются на сессию и подставляются в следующие вызовы (удобно для строки подключения к ИБ); `nocache: true` — вызов самодостаточен; `cache_show` / `cache_clear`.
- Длинные команды: `&MCPДлительная(Таймаут = 600)` — фон через отдельный процесс `oscript <CLI-вход> ...`, возвращает `taskId`, живой лог, авто-отмена по дедлайну.
- Прогресс: каждое INFO-сообщение шлёт `notifications/progress` (клиент сбрасывает таймаут).
- Хинты: `&MCPТолькоЧтение`, `&MCPРазрушающая`, `&MCPИдемпотентная`, `&MCPВнешнийМир`, `&MCPЗаголовок("...")`.

## Рецепт порта рукописного MCP → autumn-mcp

Пример из практики: `lekot/mcp-1c` (GPL-3.0, OneScript, 5 tools: `bsl_search`, `xml_search`, `config_list`, `read_module`, `syntax_help_search`; SQLite-справка через пакет `sql`).

Структура рукописного сервера (что удаляем):
```
main.os                ← цикл stdin/JSON-RPC (удаляем; заменяется точкой входа autumn-mcp)
src/Dispatcher.os      ← диспетчер methods (удаляем)
src/adapters/          ← StdioAdapter, JsonRpcSerializer, FileSystem (удаляем, кроме FileSystem-логики в хендлерах)
src/domain/            ← McpProtocol, ToolRegistry, IToolHandler (удаляем)
src/usecases/          ← InitializeSession, ListTools, CallTool (удаляем)
src/handlers/          ← бизнес-логика 5 tools (ОСТАВЛЯЕМ, переобъявляем)
src/data/shcntx_help.db← SQLite-справка (файл, переносится как есть)
```

Что остаётся в новом каркасе:
1. `#Использовать autumn`, `#Использовать autumn-mcp`, `#Использовать sql` (для syntax_help_search).
2. Для каждого handler — модуль с `&Инструмент` + `&ПараметрИнструмента` + `&ВыполнениеИнструмента`; аргументы вместо `Соответствие` становятся переменными с аннотациями.
3. `main.os` нового сервера — минимальный: `Запуск = Новый MCP_Запуск(); Запуск.Старт();` (или `MCP_Сервер`-обвязка autumn-mcp; точный API смотри в текущем README autumn-mcp).
4. Правило `.mdc` для Cursor и `opm install -f *.ospx` — переносятся без изменений (автор уже упаковал `build/opm pack/`).

Проверка после порта:
```bash
echo '{"method":"initialize","params":{"protocolVersion":"2024-11-05","capabilities":{},"clientInfo":{"name":"test","version":"1"}},"jsonrpc":"2.0","id":0}' | oscript main.os
# ожидаем result.protocolVersion == 2024-11-05
```
Далее: `tools/list` должен вернуть 5 инструментов; затем 2–3 реальных вызова (`read_module` по файлу, `syntax_help_search` по слову).

## Проверено эмпирически 2026-08-11 (спайк `C:\hermes\spike-autumn-mcp\`)

- Бутстрап (рабочий, из example репозитория): `#Использовать autumn` / `#Использовать autumn-mcp` / `#Использовать "."`, затем `Поделка = Новый Поделка(); Поделка.ЗапуститьПриложение();`. Класс `Поделка` — из самого autumn (DI-контекст); инструменты — классы в `Классы/` рядом с main.os, сканируются автоматически. Локальный исходник либы: `tools\engine\oscript-2.1.0\lib\autumn-mcp\src\Классы\MCP_*.os`.
- `initialize` возвращает `protocolVersion: 2025-03-26`, serverInfo жёстко «AutumnMCP 1.0.0» (захардкожено в MCP_Сервер.os); capabilities декларируют prompts/resources, но они пустые.
- Схема генерится рефлексией: `required` и типы корректны; блок `annotations` (title/readOnlyHint/destructiveHint/idempotentHint/openWorldHint) эмитится через `Функция АннотацииИнструмента() Экспорт`.
- Результат-`Структура`/`Массив` → `structuredContent` + текст; строка → текст; исключение в теле → `isError: true`.
- **Опциональный параметр без значения приходит как `Неопределено`** — валидировать `= Неопределено`/`ПустаяСтрока`, а не «0 = не задано» (число 0 передаётся корректно).
- Аргументы присваиваются генератором декоратора: `Свойство = ПараметрыИнструмента.Получить("имя")` (см. `ПодготовитьВыполнитьИнструмент` в MCP_ДекораторИнструментов.os).

## Питфоллы строк и аннотаций (проверено на порте mcp-1c, 2026-08-11)

- **Кавычки в аргументах аннотаций запрещены.** `ПостроительДекоратора.os` пере-сериализует строковые аргументы `&Инструмент`/`&ПараметрИнструмента` и не экранирует `"` → ошибка компиляции сгенерированного декоратора («Ожидается символ: ClosePar»). В описаниях использовать кавычки-«ёлочки» („...“) или вообще без кавычек. В теле функций удвоение `""` работает — но не в аннотациях.
- **`\"` в OneScript-строках — не escape.** Обратный слэш перед кавычкой ничего не экранирует: строка закрывается, дальше — синтаксическая ошибка. Внутри строк кавычка удваивается: `""*""`.
- **Сервисные классы без аннотаций** (например хелпер ФС) класть в Классы/ можно — autumn-mcp регистрирует только классы с `&Инструмент`, остальные просто подхватывает как обычные классы.

## Питфолл: пакет `sql` (SQLite) на oscript 2.1.0 — падает, фикс копиями DLL

Симптом: `System.IO.FileNotFoundException: System.Data.SqlClient, Version=4.6.1.6` при `Новый Соединение()` (тип SQLite). Причина: sql 1.3.2 кладёт сборки в `Components/dotnet/runtimes/win/lib/netcoreapp2.1/` (System.Data.SqlClient.dll) и `runtimes/win-x64/native/` (SQLite.Interop.dll), а резолвер oscript 2.1.0 эти подкаталоги не прощупывает. Фикс (проверен на спайке и на боевом lekot/mcp-1c — чинит его syntax_help_search):

```bash
L=/c/hermes/tools/engine/oscript-2.1.0/lib/sql/Components/dotnet
cp "$L/runtimes/win/lib/netcoreapp2.1/System.Data.SqlClient.dll" "$L/"
cp "$L/runtimes/win-x64/native/SQLite.Interop.dll" "$L/"
```

## Ограничения/грабли

- **Путь без кириллицы**: Cursor передаёт путь к main.os в искажённом виде, сервер не стартует (`C:\mcp-1c\` ок, `C:\Users\Максим\...` — нет).
- Не дублировать сервер в локальном и глобальном `.cursor/mcp.json` — Cursor запустит два процесса с одним именем, один упадёт по EOF.
- Лицензии: производная работа сохраняет лицензию оригинала (lekot/mcp-1c — GPL-3.0). autumn — своя лицензия (проверить в пакете), конфликтов нет, но копирайт автора переносим.
- `sql`-пакет остаётся внешней зависимостью (autumn-mcp БД не трогает).
- `web_extract` не отдаёт контент (SearXNG-backend) — README через `raw.githubusercontent.com/<owner>/<repo>/HEAD/README.md`.
