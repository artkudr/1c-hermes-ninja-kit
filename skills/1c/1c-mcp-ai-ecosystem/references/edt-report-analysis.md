# Анализ отчётов из EDT-проекта без рантайма (проверено 2026-08-11 на qbik-dev)

Как получить «что использует отчёт» (регистры/справочники/документы) статически, без запуска базы, — из EDT-выгрузки конфигурации. Это **реально новое поле для autumn** (в отличие от «обёрток над toolkit», см. `analytics-mcp-oscript-feasibility.md`): статическая XML-индексация отчётов.

## Структура СКД-отчёта в EDT-проекте

```
src/cf/Reports/<Отчёт>/
├── <Отчёт>.xml                               ← метаданные отчёта (имя, синоним)
├── Ext/Module.bsl                            ← код отчёта (читает существующий read_module)
└── Templates/ОсновнаяСхемаКомпоновкиДанных/
    ├── ОсновнаяСхемаКомпоновкиДанных.xml     ← дескриптор шаблона (1.4 КБ, пустой)
    └── Ext/Template.xml                      ← СКД: поля + ТЕКСТ ЗАПРОСА (десятки-сотни КБ)
```

**Ключевое**: настоящий контент СКД — в `Templates/ОсновнаяСхемаКомпоновкиДанных/Ext/Template.xml`, а не в `<Отчёт>.xml` и не в дескрипторе `ОсновнаяСхемаКомпоновкиДанных.xml` (тот только `<Template uuid=...><Name>ОсновнаяСхемаКомпоновкиДанных</Name></Template>`, 15 строк). Проверено: 121 КБ / 2650 строк у `ABCXYZАнализПродаж`.

## Что извлекается из Template.xml

Namespace: `http://v8.1c.ru/8.1/data-composition-system/schema`.

- **Наборы данных**: `<dataSet xsi:type="DataSetQuery">` (запросные) / `DataSetObject` (объектные); имя набора `<name>ДанныеПоПродажам</name>`.
- **Поля**: `<field xsi:type="DataSetFieldField">` с `<dataPath>«Номенклатура</dataPath>`, `<field>`, `<title><v8:content>Синоним поля</v8:content>`, роль `<dcscom:dimension>` (измерения) / ресурсы (итоги) — 28 полей / 1 DataSetQuery в примере.
- **Текст запроса**: элемент `<query>` (в примере — CData-подобный текст, ищется regex `<query>(.*?)</query>` по-секционно): `ВЫБРАТЬ ПродажиОбороты.Период КАК Период … ИЗ РегистрНакопления.Продажи.Обороты …` → **какие регистры/справочники/документы трогает отчёт, видно без запуска**.

## Признаки и пифоллы

- **Бинарные метаданные НЕ нужны**: EDT-проект хранит отчёты как XML + папки; oscript читает нативно (`ЧтениеXML`/regex). Полный обход `find src/cf/Reports -name 'Template.xml'` — за несколько секунд (на большом проекте grep по всему `Reports/` может уйти в таймаут — сужать `-path '*/Templates/ОсновнаяСхемаКомпоновкиДанных/Ext/Template.xml'`, а не весь каталог).
- **СКД-отчёты** разбираются полностью. **Отчёты-«самопалы»** (без СКД, табличный документ кодом) — их «структура» только в BSL-модуле → покрываются `bsl_search`/`read_module` (регистры видны в тексте запросов кода).
- **Внешние .epf/.erf** — бинарный контейнер 1С (сигнатура `FF FF FF 7F`, не zip!), oscript их не читает (нет бинарных примитивов в ядре). Пути: конфигуратор → «Сохранить как XML», либо держать в EDT-проекте. Подробности → `oscript-engine-capabilities.md`.
- Макеты-табличные документы в `Templates/*/Ext/` тоже XML, но для аналитики бесполезны (печатные формы).

## Дизайн инструментов autumn («Аналитика отчётов»)

| Инструмент | Что делает | Источник | Сложность |
|---|---|---|---|
| `report_list(path)` | Дерево отчётов: имя + синоним | `Reports/*.xml` (метаданные) | 🟢 (вариация config_list) |
| `report_data_sources(path, отчёт)` | Регистры/справочники/документы, которые использует отчёт | regex по `<query>` из Template.xml | 🟢-🟡 (паттерны `Регистр\.[A-Za-zА-Яа-яЁё_]+` и т.п., уже опробованы) |
| `report_structure(path, отчёт)` | Поля СКД: измерения/ресурсы/типы | `<field>` из Template.xml | 🟡 (XML деревом) |
| `report_find(path, текст)` | Поиск по отчётам (синоним/поля/источники) | FTS5-индекс по XML-папкам отчётов | 🟡 (FTS5 уже есть для справки) |

Для расширения (`src/cfe/*/Reports`) — та же логика. Ответы аналитика: «какие отчёты используют регистр Продажи», «где считается валовая прибыль», «что за поля в ТоварныйОтчёт».
