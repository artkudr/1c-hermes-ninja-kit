# Шаблон 1С-проекта: структура папок и координатор

> **Главный принцип работы: диск — единственный источник истины.**
> Сессия в Hermes — лишь удобный инструмент взаимодействия с документацией.
> Всё ценное (запросы, решения, планы, скрины, файлы заказчика) лежит в папках
> проекта, а не в истории чата. Сессию можно удалить — проект останется целым.

## Именование

- **Папки и файлы — латиницей** (`task_1`, `request.md`, `materials/`), чтобы
  не мучиться с путями в скриптах, git, docker и в именах файлов заказчика.
- **Русское название задачи — только строкой** внутри файлов: карточка задачи
  (поле «Название») и координатор (колонка «Название»). В именах его нет.

## Дерево проекта

```
<Проект>/
├── src/
│   ├── cf/                  # выгрузка типовой конфигурации (read-only, не в git)
│   └── cfe/<Расширение>/    # рабочие расширения (это редактируем и линтуем)
├── reports/                 # отчёты анализа (json/sarif, не в git)
├── notes/                   # интеллект-центр проекта (в git)
│   ├── registry.md          # реестр базы: версия типовой, состав расширений
│   └── state.md             # ★ КООРДИНАТОР — весь стейт проекта в одном файле
├── docs/                    # общий каталог документации (не по задачам)
└── tasks/                   # все задачи, по папке на каждую
    ├── task_1/              # задача = папка: всё сопровождение вместе
    │   ├── README.md        # карточка: статус, план, сделано, осталось
    │   ├── request.md       # исходный запрос (аналитик/пользователь) + скрины
    │   ├── solution.md      # как вяжется с кодовой базой (объекты, расширение)
    │   ├── assets/          # скриншоты базы, картинки из запроса
    │   ├── materials/       # файлы от заказчика/разработчика (excel, pdf, docx)
    │   └── _archive/        # устаревшие версии, старые материалы
    └── task_2/ ...
```

## Правила ведения

1. **Задача = папка.** Всё по задаче — внутри одной папки, не раскидывается.
2. **Ключ задачи** `task_N` — латиницей; используется в: имени папки, заголовке
   сессий Hermes (для поиска), строках координатора. Русское название — только
   строкой в карточке и state.md.
3. **Карточка задачи** (`task_N/README.md`) — план, статус, что сделано, что
   осталось. Обновляется каждый раз, когда с задачей что-то происходит.
4. **Запрос не переписываем.** Исходный текст запроса аналитика/пользователя
   хранится как есть (request.md), скрины базы — в assets/. Так ничего не потеряется.
5. **Координатор проекта** (`notes/state.md`) держит сводную картину всех задач —
   статусы, приоритеты, что в работе сейчас. Обновляется при каждом закрытии/открытии задачи.

## Как создать базу по этому эталону

```bash
# эталон живёт в ninja-kit: templates/project/
# рабочая база создаётся командой кита (структура src/cfe + notes + tasks)
ninja new <ИмяБазы> --ext <Расширение>
# ОБЯЗАТЕЛЬНО далее: создать Hermes-проект с якорем на папку базы
# (project_create), проверить pwd = корень базы. Без этой привязки база
# не работает как проект Hermes.
# далее: src/cf ← типовая, src/cfe/<Расширение> ← рабочая выгрузка EDT,
#        notes/registry.md — версия типовой и состав расширений
#        notes/state.md — координатор уже создан, добавить первую задачу
```

Каркас задачи (`tasks/task_N/`) — копировать с примера `templates/project/tasks/task_1/`.

## Связь с инструментами

- **Hermes-проект** = каталог базы (проект = база, переключение = смена каталога).
- **Анализ кода** — статический контур mcp-1c (lekot): `bsl_search`, `read_module`
  (srcDir = `src/cfe/<Расширение>`, контекст типовой = `src/cf`), отчёт — в `reports/`.
- **AGENTS.md** — правила для ИИ-агентов (копировать из `AGENTS.md.tpl` при реальном запуске).
